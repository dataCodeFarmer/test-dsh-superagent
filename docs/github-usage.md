# 通过 GitHub 提交任务与查看结果

本仓库用于测试 `dsh-superagent` 的协作流程，目前仅包含文档，没有需要安装或运行的应用。你可以在本仓库的 GitHub Issue 中提交范围明确的小任务，由代理创建 PR（Pull Request，拉取请求），再由人工审核和合并。

## 1. 准备工作

- 使用可以访问本仓库并发布 Issue 或评论的 GitHub 账号。
- 确认代理已配置为处理本仓库的 GitHub 请求，且你的账号有权触发任务。提及代理不等于所有账号的请求都会被接收；没有收到回应时，请联系仓库维护者确认配置。
- 本仓库的代理 GitHub 账号为 `@duspring`；不要在 GitHub 中使用飞书里的 `@dsh-superagent` 作为任务接收账号。

## 2. 提交任务

在本仓库的 **Issues** 页面新建 Issue，在正文中提及 `@duspring`，写清楚：

- **目标**：需要修改的文件或解决的问题。
- **期望结果**：怎样才算完成。
- **限制条件**：哪些内容应保留，哪些改动不应进行。
- **交付方式**：要求创建 PR，并把链接回复到当前 Issue。

例如：

```text
@duspring 请在 README.md 中增加一段中文项目简介，保留现有内容。
完成后创建 PR，并在本 Issue 回复链接。
```

如果任务已经写在现有 Issue 正文中，也可以在该 Issue 下添加评论：

```text
@duspring 请按本 Issue 正文执行任务，完成后创建 PR，并在这里回复链接。
```

优先提交小而明确的任务，避免在多个 Issue 中重复提交同一请求。不要在 Issue、评论或预期提交的文件中放入密码、访问令牌或私密聊天内容。

## 3. 查看结果与补充信息

在原 Issue 中查看代理回复。收到任务确认不代表任务已经完成；当修改可供审核时，代理会回复 PR 链接。如缺少必要信息或访问权限，请在提出问题的原对话中补充。

打开结果 PR 后：

1. 阅读 PR 描述，确认改动范围、验证情况及已知限制。
2. 在 **Files changed** 中逐项检查修改是否符合任务要求。
3. 查看可用的自动化检查结果；没有配置检查不代表修改已经验证通过。
4. 如需调整，在 PR 中留下具体审核意见，指出位置、问题及期望结果。

PR 已创建不代表任务已完成或修改已合并。标为 **Draft** 的 PR 尚未准备好供正式审核；如代理说明工作受阻，按原对话中的要求提供必要信息或权限，不要把未完成的草稿当作最终结果。

## 4. 人工审核与合并

由人工审核者确认修改符合预期、必要反馈已处理，并检查仓库要求的检查结果，再由有权限的人员执行合并。代理不会代替人工批准或合并 PR，也不会启用自动合并。

合并后，确认 PR 状态为 **Merged**，并在目标分支查看最终内容。**Closed** 但未合并的 PR 不表示修改已经进入目标分支；没有合并权限时，请联系仓库维护者。
