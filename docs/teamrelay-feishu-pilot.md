# TeamRelay 协舟：飞书私聊文档任务试点

本指南说明如何通过飞书私聊提交文档任务，由维护者在工作台启动执行、审阅差异并确认发布草稿 PR（拉取请求）。

## 1. 私聊发起文档任务

打开与机器人 **TeamRelay 协舟** 的私聊，使用 `/teamrelay` 前缀发送需求。写清目标文件、期望结果、需保留的内容和修改边界。

```text
/teamrelay 请在 README.md 中补充项目简介，保留已有有效内容，仅修改该 Markdown 文件，生成草稿 PR 供维护者审阅，不要自动合并。
```

收到回执后，保留任务编号及其中的工作台链接。收到回执不代表已执行或已生成 PR。

## 2. 用 TR 编号补充同一任务

在私聊中使用以下格式续办，避免将补充要求作为新任务提交：

```text
/teamrelay TR-1001 具体补充要求
```

`TR-1001` 是任务编号示例，实际使用时替换为已收到的编号；将“具体补充要求”替换为本次要补充的内容，例如限定简介长度、保留某个章节或缩小修改范围。

## 3. 在工作台查看并启动执行

1. 点击飞书回执中的工作台链接，查看任务进展。
2. 由维护者核对任务目标、补充要求和允许修改的文件范围。
3. 确认需求后，由维护者点击 **开始文档执行**。

当前不支持自然语言状态查询命令；查看进展请使用回执中的工作台链接，不要通过私聊询问状态来代替工作台查看。

## 4. 审阅差异并生成草稿 PR

1. 执行后，由维护者在工作台逐项检查文档差异，确认满足原始需求及补充要求，且保留已有有效信息。
2. 检查是否出现越界文件、无依据的说明或敏感信息；存在问题时，先用对应 TR 编号补充修订要求。
3. 差异检查通过后，由人工确认发布草稿 PR。
4. 由维护者审阅生成的草稿 PR，核对文件范围和最终差异。草稿 PR 已生成不代表审核通过或已经合并。

## 5. 执行边界

- 当前仅允许新增或修改 `README.md`、`README.<语言>.md` 以及 `docs/` 下的 Markdown 文件。
- 不删除文件，不修改源码、配置或工作流，不运行命令。
- 不编造启动命令、端口、功能或测试结果。
- 不在任务或文档中填写内网地址、个人信息、密码、访问令牌或私密聊天记录。
- 执行由维护者启动；发布草稿 PR 前必须人工检查差异并确认。
- **不能自动合并**。最终是否合并由人工审阅决定，并由有权限的维护者操作。
